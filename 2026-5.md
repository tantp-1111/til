# 実装内容について
家族グループのなかでオーナーとメンバーの二つの役割を用意した。オーナーはグループ内のオーナー及びメンバーを脱退させることができる、メンバーからオーナーへ昇格、オーナーからメンバーへ降格もできる。メンバーは自分自身の脱退のみ可能。
ここで考えなければならないのは、グループ内でオーナーが一人しかいない場合、
- そのオーナーが脱退する場合の挙動
- そのオーナーが自分をメンバーに降格させる場合の挙動
この二つについては実施できないようにし、フラッシュメッセージでなぜできないのかを明示した。

家族グループでの投稿のみを表示する機能を追加

**:bulb: 理解できたこと**
ルーティングではindexのみをつくり、詳細ページは個人のmemoriesの詳細ページに飛ぶ設計にしました。この詳細ページの認可の基準を緩めることで実装可能にしました。
```
class MemoryPolicy < ApplicationPolicy
  def show?    = record.published? || owner? || (record.unlisted? && family_member_of_owner?)

  private

  def owner?
    return false if user.nil?
    record.user_id == user.id
  end

  # current_user の所属家族グループと record.user の所属家族グループに重複があるか。
  # 「1 ユーザー 1 グループ」制約下では、実質「同じ家族グループに属しているか」の判定。
  def family_member_of_owner?
    return false if user.nil?
    user.family_groups.where(id: record.user.family_groups.select(:id)).exists?
  end
end
```
`family_member_of_owner?`の中を
```
user.family_group_id == record.user.family_group_id
```
としていないのは、今後１ユーザーが複数グループを持つ設計になってもPolicyをほぼ変更しなくて良いからです。

**:pushpin: 今日やったこと**
ミニメモリ（投稿）に子供を選択できる機能を追加

**:bulb: 理解できたこと**
- 投稿にこどもを紐付け（多対多）
投稿はこどもを設定しなくてもいい状態かつ、一つの投稿に複数のこどもを結びつけられる状態する設計にしたので多対多の中間テーブルを作成
- 子供を選択するUIはバッジ形式にし、直感でわかりやすい設計
JSで実装。disabledつけない方が良かった・・・
- こどもを複数可、未選択可にしたことで行き詰った点
最初、memoryコントローラのストロングパラメータに
```
def memory_params
    params.require(:memory).permit(:title, :description, :memory_date, :visibility, :image, child_ids: [])
  end
```
と書いていました。
memoryの新規投稿および編集viewに
```
<input type="hidden" name="memory[child_ids][]" value="">
```
と書いており、child_idsを入れるための空配列を用意しています。
空配列だから何も入っていないと思っていたのですが、
value が空でも配列の要素として送信されます。つまりchild_ids: [""]となっている。
だから、""という空文字が送信されるとその空文字も一つのレコードとして認識してしまうのでよくない！
なのでストロングパラメータに空文字を除去するコードを追加しました。
```
def memory_params
    params.require(:memory).permit(:title, :description, :memory_date, :visibility, :image, child_ids: []).tap do |whitelisted|
      # 空文字列を除外
      whitelisted[:child_ids]&.reject!(&:blank?)
    end
  end
```
child_ids: ["", "1", "2"]と送信されてもchild_ids: ["1", "2"]となり、空文字が除去され正しくデータベースに送られるようになりました。
またこどもを未選択で送信した場合、child_ids: [""']で送信されたあと、ストロングパラメータで空文字が除去されchild_ids: []となり、こどもとの関連付けがなくなります。
ちなみに、
```
<input type="hidden" name="memory[child_ids][]" value="">
```
がないと、子供を1人も選択しなかった場合に child_ids パラメータ自体が送信されないので編集時に未選択にしたあと更新すると正しく更新されません。ここで詰まった。
